# Work Knowledge Base

이 레포지토리는 업무 관련 자료, 논문 리뷰, 기술 검토 및 프로젝트 비즈니스 모델을 통합하여 관리하는 중앙 지식 저장소입니다.

## 🗂 레포지토리 구조 및 관리 원칙

자료의 지속적인 축적과 가독성을 위해 아래의 구조와 원칙을 따릅니다.

### 1. 디렉토리 구조
```text
work/ 
├── index.html                   # 🌟 통합 대시보드 (진입점)
├── README.md                    # 레포지토리 구조 및 관리 규칙
├── assets/                      # 전역 공통 에셋 (이미지, CSS 등)
├── templates/                   # 일관된 문서 작성을 위한 템플릿 모음
│
├── 01_ihx/                      # 내부 열교환기 관련 자료
├── 02_hvac_bm/                  # 공조 시스템 비즈니스 모델 (BM)
├── 03_research_paper/           # 논문 정리 및 리뷰
└── 04_cooling_tower/            # 냉각탑용수 절감 기술 검토
```

### 2. 관리 규칙 (Rules)

1. **Numbering (순번 부여)**: 
   - 최상위 주제(카테고리) 폴더를 생성할 때는 반드시 `01_`, `02_` 와 같이 두 자리 숫자로 시작하는 prefix를 부여하여 강제 정렬합니다.
2. **지역성 (Locality) 유지**: 
   - 특정 프로젝트(예: `01_ihx`)에서만 사용되는 이미지나 데이터 파일은 해당 폴더 하위의 `assets/` 디렉토리에 저장합니다. 
   - 전역적으로 쓰이는 이미지만 루트의 `work/assets/`에 저장하여 의존성 꼬임을 방지합니다.
3. **템플릿 활용**: 
   - 새로운 주제 폴더를 추가할 때는 `templates/`에 있는 대시보드 양식을 복사하여 `index.html`로 사용합니다.
   - 이를 통해 전체 페이지의 UI/UX 일관성을 유지합니다.
4. **Markdown 중심 작성**: 
   - 세부 내용은 가급적 `.md` 파일로 작성하여 GitHub에서 즉시 렌더링되도록 하며, 필요한 경우에만 HTML을 병행 사용합니다.
